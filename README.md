# attackshark-driver

Нативный Linux-драйвер для периферии Attack Shark, которая официально
поддерживается только веб-драйверами (WebHID). Работает напрямую через
`hidraw`, без Wine, браузера и проприетарного софта.

## Поддерживаемые устройства

| Устройство | VID:PID | Платформа |
|---|---|---|
| Attack Shark R85 HE | `3151:5029` | Royuan RY5088, GearHub |
| Attack Shark R11 Ultra (2.4 ГГц) | `3554:fb43`, `3554:fb44` | Compx, Control HUB |
| Attack Shark R11 Ultra (кабель) | `3554:f5f6` | Compx, Control HUB |
| Attack Shark R11 Ultra (Bluetooth) | `3554:f533` | HOGP — только ввод, без настроек (см. ниже) |
| Attack Shark X11 Ultra | `3554:f517`, `3554:f515` | Compx, Control HUB |
| прочие клавиатуры Royuan | `3151:*` | GearHub |

Устройства определяются по VID семейства (`0x3151` — клавиатуры Royuan,
`0x3554` — мыши Compx) и по вендорской коллекции в дескрипторе HID
(`0xFFFF/0x02` у клавиатур и `0xFF02` у мышей), поэтому новые PID в этих
семействах обычно работают без правок кода.

Составное устройство показывается одной строкой. Например, R85 HE — это
три HID-интерфейса (boot-клавиатура, потребительские/системные клавиши и
вендорская коллекция настроек), то есть три узла `/dev/hidraw` с одним и
тем же `3151:5029`. Драйвер склеивает узлы одного физического устройства
по `HID_PHYS` и оставляет тот, в котором есть вендорская коллекция, так что
в списке (`attackshark list` и GUI) на одну клавиатуру приходится ровно
одна строка.

### Bluetooth

`attackshark list` показывает мышь и по Bluetooth, но настроек по этому
каналу нет: в HID-дескрипторе, который R11 Ultra публикует через HOGP,
вендорская коллекция `0xFF02` отсутствует (карта из 202 байт содержит
только клавиатуру, потребительские клавиши, системные клавиши и мышь), а в
GATT нет вендорского сервиса — только GAP, GATT, Device Information, Battery
и HID. Поэтому по Bluetooth драйвер показывает устройство и объясняет
причину, а DPI, частота опроса и подсветка меняются через приёмник 2.4 ГГц
или кабель `3554:f5f6`. Уровень заряда по Bluetooth виден в `bluetoothctl
info` и `upower -d` (сервис Battery `0x180f`).

## Возможности

**Мышь (R11 Ultra и родственные Compx):**

- `info` — прошивка, версия донгла, состояние связи, батарея, DPI, LOD,
  debounce, motion sync, angle snap, ripple, подсветка, профиль;
- `battery`, `dpi`, `rate`, `lod`, `debounce`, `motion-sync`, `angle-snap`,
  `ripple`, `sleep`, `effect`, `light`;
- `dump`, `backup`, `restore` — чтение и запись 256-байтного блока настроек;
- `raw` — произвольная 16-байтная команда (отладка).

**Клавиатура (R85 HE и родственные Royuan HE):**

- `info` — прошивка, профиль, частота опроса, debounce, режим магнитов,
  подсветка;
- `light` — режим, яркость, скорость, цвет, dazzle; `light on|off` включает и
  выключает подсветку целиком (отдельная команда low-power). На проверенном
  R85 HE зона подсветки под клавишами на запись не реагирует — настройки
  сохраняются, но светодиоды не меняются; работает боковая подсветка
  (`side-light`);
- `side-light` — боковая подсветка R85 HE: режим, яркость, скорость, цвет,
  dazzle;
- `rate`, `profile`, `debounce`, `magmode`;
- `travel` — ход срабатывания, отпускания, Rapid Trigger, deadzone для всех
  клавиш (без аргументов показывает текущие значения). Шаг значений драйвер
  определяет сам по версии прошивки: 0.1, 0.01 или 0.005 мм;
- `keys` — таблица всех клавиш: имя, ход, Rapid Trigger и пара Snap Tap;
- `key KEY` — те же параметры для одной клавиши, остальные не меняются;
- `snap KEY1 KEY2 [last|neutral|first|second]` — Snap Tap для пары клавиш,
  `snap off KEY` снимает пару. Устройство само решает, какая из двух клавиш
  остаётся нажатой, пока удерживаются обе: последнее нажатие, нейтрально,
  первая или вторая клавиша;
- `multi` — сырая таблица магнитов по параметру;
- `stream` — живой мониторинг хода клавиш (аналоговый поток);
- `reset` — сброс к заводским настройкам.

Любая команда поддерживает `--json`, все команды можно выполнять из файла
через `attackshark apply FILE`. Глобальные `--json` и `--optional` можно
указывать перед командой или после неё. Разделитель `--` завершает разбор
глобальных флагов, например `attackshark --json mouse backup -- --optional`.
Чтение `keyboard travel` показывает слот 0 и признак `uniform` в JSON;
если значения слотов различаются, используйте `keyboard keys` для деталей.

## Сборка и установка

```sh
make            # соберёт ./attackshark (и GUI, если есть GTK4)
make gui        # только GUI: ./attackshark-gui
make test       # кодеки, CLI, протокол и многопоточные таймауты без устройств
make test-ui    # GUI, очередь, состояние и время жизни окон на mock-устройствах
make test-store # аппаратный smoke-тест, повторяет текущую частоту опроса
sudo make install
sudo make install-gui     # бинарник, .desktop и иконка
```

`make install` ставит бинарник в `/usr/local/bin`, правила udev
(`/etc/udev/rules.d/70-attackshark.rules`), юнит
`/etc/systemd/system/attackshark.service` и загрузочный профиль
`/etc/attackshark.conf`. Существующий профиль не перезаписывается и не
удаляется при `make uninstall`. Каталог профиля можно изменить через
`CONFDIR`; сервис будет читать профиль из выбранного каталога.
Для установки в дерево пакета поддерживается `DESTDIR`.

Если ставите драйвер не из пакета (или просто распаковали архив), правила
udev руками копировать не нужно: драйвер ставит их сам.

```sh
sudo attackshark permissions          # нужны ли правила этому пользователю
sudo attackshark permissions install  # записать правила и перезапустить udev
```

В GUI это одна кнопка: при `permission denied` сверху появляется баннер
«Нет доступа к устройствам: нужны правила udev» с кнопкой «Исправить». Она
запускает тот же установщик через `pkexec` (пароль администратора), после
чего hidraw-узлы, уже подключённые к системе, сразу получают доступ —
переподключать и перелогиниваться не нужно. Если GUI запущен от root,
драйвер исправляет права сам, без вопроса. Запрос пароля в GUI подписан
через polkit (`data/org.attackshark.permissions.policy.in`), поэтому
пользователь видит, зачем его спрашивают, а не безликое «pkexec».

Правила используют `TAG+="uaccess"` из systemd-udevd: доступ получает
активный пользователь сессии. Там, где uaccess нет (без systemd), нужно
своё правило с группой — но тогда его пишет уже администратор, а не драйвер.

Имя файла правил выбрано не случайно: он должен читаться **до**
`73-seat-late.rules`. Именно это правило запускает встроенную команду
`uaccess`, и только для тегов, выставленных файлами, прочитанными раньше.
Файл с большим номером (прежний `99-attackshark.rules`) менял только режим
узла, ACL не выдавался, и узел оставался доступным лишь root: кнопка
«Исправить» отрабатывала, но доступа не появлялось. Поэтому правила
дополнительно сами просят `RUN{builtin}+="uaccess"` — так они работают и
после переименования файла дистрибутивом. Прежний файл с номером 99
установщик удаляет, а `permissions status` не считает его установленным.

Правила сопоставляются по VID семейства (`3151` — клавиатуры Royuan,
`3554` — мыши Compx), а не по конкретному PID, поэтому новая модель или
новая прошивка с другим product id больше не требует ни новых правил, ни
нового файла. Атрибут `ATTRS{id/vendor}` — атрибут шины HID, он есть у
родителя любого hidraw-узла, поэтому одно правило открывает устройство и
по кабелю, и через приёмник 2.4 ГГц, и по Bluetooth.

У CLI зависимостей нет: используется только `hidraw`, `ioctl` и `select`.
GUI требует GTK4 и libadwaita; если их нет, `make` просто собирает CLI.

## Быстрый старт

```sh
attackshark list
attackshark mouse info
attackshark keyboard info

attackshark mouse rate set 8000
attackshark mouse dpi set 1 1600
attackshark mouse motion-sync on
attackshark mouse light --mode 1 --color ff0000 --brightness 6 --speed 3

attackshark keyboard rate 8000
attackshark keyboard light --mode wave --brightness 3 --speed 2 --color 00a0ff
attackshark keyboard travel --actuation 1.5 --rt --rt-press 0.2 --deadzone 0.2
attackshark keyboard keys                 # что сейчас задано на каждой клавише
attackshark keyboard key 9 --actuation 2.0 --release 2.0 --deadzone 0.3
attackshark keyboard snap 9 21 last       # Snap Tap: пара A и D
attackshark keyboard snap off 9           # снять пару с клавиши A
```

Полный список: `attackshark --help`. Проверка прав доступа и установка
правил udev — `attackshark permissions` / `attackshark permissions install`.

## Графический интерфейс

`attackshark-gui` — настройка тех же параметров мышкой, с живым состоянием
устройства: список подключённых мышей и клавиатур, заряд и связь, частота
опроса, DPI по этапам, LOD, debounce, motion sync/angle snap/ripple, а у
клавиатуры — ещё и подсветка. Ход клавиш задаётся для всех клавиш сразу или
для одной выбранной из списка; рядом находится Snap Tap с выбором второй
клавиши и приоритета. Подсветка мыши в GUI не выводится: у части моделей
(например, R11 Ultra) её физически нет, поэтому она остаётся командой
`attackshark mouse light`.

```sh
make gui && ./attackshark-gui
```

Если hidraw-узлы принадлежат root, сверху окна появляется баннер «Нет
доступа к устройствам: нужны правила udev» с кнопкой «Исправить»: она
ставит правила через `pkexec` и сразу открывает доступ к уже подключённым
устройствам. В списке одно физическое устройство занимает одну строку.

GUI линкуется с тем же драйвером, что и CLI, поэтому оба инструмента
одинаково видят устройства и настройки. У каждого устройства своя очередь
и фоновый поток: спящая мышь не блокирует клавиатуру и демо-свитч.
Подробности архитектуры и
того, как добавить новую настройку, — в `docs/GUI.md`.

## Профиль при загрузке

`etc/attackshark.conf` — пример конфигурации: по одной команде CLI на строку.
Установленный юнит применяет его при старте системы (`--optional`: если
устройство не подключено, остальные строки всё равно выполняются).

```ini
mouse rate set 8000
mouse dpi set 1 800
keyboard light --mode wave --brightness 3 --speed 2 --color 00a0ff
keyboard travel --actuation 1.5 --rt --rt-press 0.2 --deadzone 0.2
```

```sh
sudo cp etc/attackshark.conf /etc/attackshark.conf
sudo systemctl enable --now attackshark.service
```

## Как это работает

Драйвер не является модулем ядра: он использует штатный `hidraw` и
вендорские HID-коллекции, которые ядро и так пробрасывает в userspace.
Кратко:

- **R11 Ultra** — «Control HUB» протокол: 16-байтные пакеты с report ID 8,
  команды чтения/записи EEPROM, DPI, частоты опроса, подсветки. Формат,
  контрольные суммы и коды частот — в `docs/PROTOCOL.md`.
- **R85 HE** — «GearHub» протокол: 64-байтные feature-отчёты, команда в
  байте 0, контрольная сумма `0xFF - sum(...)` в байте 7 (подсветка — в
  байте 8), плюс аналоговый поток хода клавиш через report ID 5.

## Ограничения и состояние проверки

- Мышь R11 Ultra проверена на реальном образце (`3554:fb44`/`fb43`):
  handshake, состояние связи, прошивка v3.01, батарея и напряжение,
  профиль, DPI, частота опроса, LOD, debounce, motion sync, angle snap,
  ripple, подсветка (чтение и запись), а также резервное копирование и
  восстановление всех 256 байт настроек — побайтно идентично. Кодек DPI
  сверен с эталонными записями прошивки, включая `42000 -> a3 a3 55 ba`.
- Клавиатура R85 HE проверена полностью: чтение состояния, подсветка,
  частота опроса, профиль, debounce, режим магнитов, ход клавиш и Rapid
  Trigger (запись + чтение подтверждены), сброс к заводским настройкам.
- Параметры мыши (DPI, частота, LOD и т.д.) читаются и пишутся только когда
  мышь включена: донгл отвечает за связь, но настройки хранятся в мыши.
  При выключенной мыши `mouse info` показывает `link offline`.
- Конфигурационный эндпоинт клавиатуры может «зависнуть», если слать
  запросы слишком часто (это умеет и OpenRGB при старте). Переподключение
  клавиатуры возвращает его в строй; драйвер сам читает не больше одного
  отчёта на команду.
- Заводские значения R85 HE: actuation 2.0 мм, release 2.0 мм, deadzone
  0.3 мм, Rapid Trigger выключен. `keyboard reset` возвращает их.
- Не реализованы: макросы, переназначение клавиш/кнопок, OLED/экранные
  эффекты, калибровка магнитов, обновление прошивки. Это отдельный объём
  работы.

## Диагностика

**«permission denied»** — пользователю не разрешено открывать узел
`/dev/hidraw*`. Правила udev ставит сам драйвер:

```sh
sudo attackshark permissions install
```

или кнопка «Исправить» в окне GUI (то же самое через `pkexec`). Проверить
состояние: `attackshark permissions`.

**`link offline`, нет батареи/DPI** — мышь выключена или спит. Включите её
и пошевелите, затем повторите команду.

**Клавиатура: «configuration endpoint did not answer»** — переподключите
клавиатуру по USB. Если до этого вы меняли ход клавиш, после переподключения
проверьте `attackshark keyboard travel` и при необходимости верните заводские
значения (`--actuation 2.0 --release 2.0 --deadzone 0.3`). Если помогает только закрытие другой программы, значит
устройство уже открыто (например, OpenRGB держит `/dev/hidraw6`).

**OpenRGB** определяет R85 HE как Skyloong GK68HE Pro и занимает ту же
коллекцию. Совместная работа возможна, но при зависании конфигурационного
эндпоинта закройте OpenRGB и переподключите клавиатуру.

## Структура

```
include/attackshark.h   API драйвера
src/hidraw.c            поиск hidraw-узлов, feature/interrupt обмен
src/mouse.c             протокол мыши (Control HUB)
src/keyboard.c          протокол клавиатуры (GearHub)
src/util.c              строки ошибок, названия моделей и режимов
src/internal.h          внутренние помощники (поиск узлов, сканирование)
src/udev.c              правила udev: текст, установка, проверка состояния
src/main.c              CLI
src/gui/                GUI на GTK4 (воркер, реестр устройств, страницы)
tests/test_codec.c      тесты кодеков
data/                   .desktop, иконка GUI, policy-файл polkit для pkexec
udev/, systemd/, etc/   установка и автозапуск
docs/PROTOCOL.md        описание протоколов
docs/GUI.md             архитектура GUI
```
